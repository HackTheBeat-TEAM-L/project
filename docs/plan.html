HYPE⁠WAVE 관중의 환호(데시벨 스파이크)를 감지해, 그 순간의 곡과 비슷한 곡을 골라 끊김 없이 다음 곡으로 이어 트는 파티용 오토 DJ.

v1.0 · 서비스 로직 확정 · Spotify + 무료 LLM 기반
10초 평균(베이스라인)Loud함성 = 트리거
확정 로직

서비스 루프

시작부터 다음 곡 재생까지, 확정된 8단계. 각 단계의 규칙과 데이터 출처가 고정돼 있습니다.

01

시작 · 장르 입력

호스트가 실행 시 입력란에 음악 장르 키워드를 입력. 이 키워드로 첫 곡을 추천받아 재생 시작. 재생 계정은 Spotify Premium(최초 1클릭 필요).

입력 → LLM → Spotify
02

실시간 데시벨 측정

마이크 수음을 실시간 측정하며 직전 10초 롤링 평균(베이스라인)을 유지.

Web Audio
03

트리거 판정

현재 순간 dB가 직전 10초 평균보다 +10(설정값) 이상 급상승하면 함성·호응으로 판정 → 트리거 발생.

자체 로직
04

쿨다운 30초

트리거 후 30초간 재트리거를 무시. 하나의 함성이 여러 번 잡히거나 연발되는 것을 방지.

타이머
05

현재 곡 파악

그 순간 재생 중인 곡을 Spotify 재생 상태에서 읽음. 우리가 튼 곡이라 이미 알고 있음 → 오디오 인식(샤잠) 없음.

Spotify · currently-playing
06

LLM 추천 2곡

무료 LLM API에 "이 곡과 비슷한 곡 2개 추천"을 요청 → 곡 이름으로 1순위·2순위 2곡을 받음. (2곡을 받는 이유는 다음 단계 검증용.)

무료 LLM (Groq/Gemini)
07

존재 검증 + URI 변환 (폴백 체인)

LLM은 없는 곡을 줄 수 있으므로, Spotify Search로 실제 존재를 검증하고 재생용 URI로 변환. 1번 → 실패 시 2번 → 둘 다 실패 시 장르 키워드로 재추천.

Spotify Search
08

다음 곡 큐잉

확정된 URI를 다음 곡으로 설정. 현재 곡은 끊지 않고, 끝나면 자동으로 이어 재생.

Spotify · 자체 큐

핵심

폴백 체인 — "없는 곡" 방어

LLM이 실재하지 않는 곡을 추천할 수 있어서 2곡을 받습니다. 곡의 존재 여부는 LLM이 아니라 Spotify Search가 검증합니다 — 검색 결과가 비면 그 곡은 "없는 곡"으로 판정하고 다음으로 넘어갑니다.

1순위

LLM 추천 1번곡 → Spotify Search

검색 결과 있음 → 그 URI를 다음 곡으로 채택. ■ 종료

2순위

1번이 없으면 → 2번곡 → Search

검색 결과 있음 → 그 URI를 다음 곡으로 채택.

폴백

둘 다 없으면 → 장르 키워드 재추천

시작 시 입력한 장르로 다시 추천 → Search → 채택. 어떤 경우에도 다음 곡이 비지 않게 보장.

이 구조 덕에 "곡이 끊기지 않게"가 실제로 성립합니다. LLM 실패·환각·API 오류 어느 쪽이든, 최소한 장르 폴백까지 내려가 반드시 재생할 곡을 확보합니다.
전제 · 제약

동작 전제

아래는 확정 로직이 성립하기 위한 전제. 데모 전 반드시 충족·인지해야 합니다.

Spotify Premium 필수

재생 계정은 정식 Premium(모바일 전용 Lite/Mini 불가). 호스트 계정 1개가 부스 역할.

HTTPS/localhost + 최초 클릭

마이크·재생 SDK는 보안 컨텍스트에서만, 재생 시작엔 사용자 클릭 1회 필요.

이름 → URI는 Search로만

LLM 결과(이름)를 Spotify Search로 URI 변환하는 단계가 필수. 빠지면 재생 불가.

상대 스파이크로 판정

마이크가 음악까지 수음하므로 절대 dB 불가. +10은 로그 스케일 기준 큰 값이라 리허설 튜닝 전제.

무료 LLM 한도·지연

Groq(빠름)/Gemini(넉넉) 무료 티어. "다음 곡" 설계라 남은 재생시간에 계산 → 지연은 흡수됨.

상업화 · 라이선스

Spotify 약관상 상업용 스트리밍 통합 제한, 현장 재생은 공연권 이슈 → "프로토타입/PoC" 프레이밍으로 대응.
