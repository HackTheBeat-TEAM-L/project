# HYPEWAVE 확정 스펙

## 1. 개요
부스 노트북(크롬) 한 대에서 도는 단일 웹앱. 파티 관중의 환호(데시벨 스파이크)를 감지해, 그 순간의 곡과 비슷한 곡을 골라 끊김 없이 다음 곡으로 이어 트는 오토 DJ.

## 2. 8단계 서비스 루프
1. **시작**: 호스트가 "음악 장르 키워드" 입력 → 그 키워드로 첫 곡을 추천받아 재생 시작. 재생 계정은 Spotify Premium. 브라우저 자동재생 정책에 따라 최초 1회 사용자 클릭 필요.
2. **실시간 데시벨 측정**: 마이크 수음을 측정해 직전 10초 롤링 평균(베이스라인) 유지.
3. **트리거 판정**: 현재 dB가 직전 10초 평균보다 +10 이상 급상승 시 트리거. (+10과 10초 윈도우는 설정값 config)
4. **쿨다운**: 트리거 후 30초간 재트리거 무시. (설정값)
5. **현재 곡 파악**: 그 순간 재생 중인 곡을 Spotify 재생 상태(currently-playing / SDK player_state)에서 읽음. (오디오 인식 금지)
6. **LLM 추천 2곡**: 무료 LLM API에 "이 곡과 비슷한 곡 2개 추천" 요청 → 1순위, 2순위 반환 (제목+아티스트).
7. **존재 검증 + URI 변환(폴백 체인)**: 
   - 1번곡 → Spotify Search(type=track). 결과 있으면 채택.
   - 없으면 → 2번곡 → Search. 결과 있으면 채택.
   - 둘 다 없으면 → 시작 시 입력한 장르 키워드로 재추천 → Search → 채택.
8. **다음 곡 큐잉**: 앱이 자체 큐를 관리하고, 현재 곡 종료 시 선정 URI로 직접 play. 중복 방지(현재 곡 + 직전 N곡 제외).

## 3. 제약 및 설정
- **Spotify**: Web Playback SDK 사용. 스코프 (streaming, user-read-playback-state, user-modify-playback-state, user-read-currently-playing). Spotify의 /recommendations 폐지됨 → 추천은 LLM으로만.
- **LLM**: Groq 또는 Gemini 사용. .env에서 키 읽음.
- **UI**: 장르 입력창, 현재 곡, 실시간 dB 미터, "HYPE!" 표시, 선정된 다음 곡, 이벤트 로그.
- **테스트**: 실제 크라우드 없이 검증할 수 있도록 "가짜 dB 주입(mock) 모드" 지원.
